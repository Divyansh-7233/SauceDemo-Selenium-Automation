# SauceDemo Selenium Automation

A Java test automation project for selected login, cart, checkout-validation, and purchase workflows on the public [SauceDemo](https://www.saucedemo.com/) training application. It uses Selenium WebDriver to drive Chrome, TestNG to run tests and manage their lifecycle, Maven to build and execute the suite, and ExtentReports to create an HTML execution report.

The normal Maven suite contains **five permanent tests**. A separate reusable demo intentionally fails so the failure-report and screenshot behavior can be demonstrated; it is excluded from the normal suite.

## Project objectives and scope

The project demonstrates how to:

- Automate important UI workflows with Selenium WebDriver and Chrome.
- Separate page-specific locators and browser actions from test assertions using the Page Object Model (POM).
- Validate user-visible behavior with TestNG assertions.
- Produce an HTML report and preserve screenshot evidence when a test fails.
- Keep a deliberate failure demonstration separate from the five-test normal suite.

This is a small UI automation project against the publicly hosted SauceDemo application. It is not a production monitoring system, load-testing suite, or runtime AI application.

## Capabilities

- Five permanent UI tests are included in the standard test run.
- A fresh ChromeDriver-backed browser session is created for each test method.
- Page objects provide operations for login, products, cart, and checkout pages.
- The base test logs pass, fail, and skipped statuses to ExtentReports.
- For failures with a running screenshot-capable WebDriver, a PNG is captured before browser shutdown and linked from the test's ExtentReports entry.
- Teardown calls `WebDriver.quit()` and stops the corresponding `ChromeDriverService`.
- ExtentReports is flushed once after the suite.
- `FailureScreenshotDemoTest` intentionally fails and is excluded from the ordinary Maven test discovery.

## Architecture and Page Object Model

The **Page Object Model** puts page-specific element locators and actions in classes under `org.pages`. Test classes describe scenarios and assert outcomes; they use those page objects instead of repeating page locators in each scenario. `BaseTest` provides common setup, reporting, failure handling, and cleanup.

In this project, Selenium sends commands to the browser, TestNG controls test execution and evaluates assertions, Maven builds the project and runs Surefire, and ExtentReports records the results in HTML. An **assertion** is a check that compares observed application behavior with an expected value; a failed assertion marks that test as failed. A **WebDriver teardown** ends the browser session with `quit()` and stops the matching ChromeDriver service.

At a high level:

1. Maven compiles the project and Surefire discovers tests matching the configured include patterns. The demo class is excluded by default.
2. TestNG invokes `BaseTest` suite and per-method lifecycle hooks.
3. `BaseTest` creates the ExtentReports test entry, starts Chrome, opens SauceDemo, and initializes page objects.
4. A test uses page objects to perform browser actions and TestNG assertions to check outcomes.
5. `@AfterMethod(alwaysRun = true)` logs the result. On a test failure, it captures and attaches the screenshot while the browser is still available; it then quits WebDriver and stops the ChromeDriver service.
6. `@AfterSuite` flushes ExtentReports to disk.

The detailed flow and component responsibilities are documented in [docs/architecture.md](docs/architecture.md).

## Permanent test cases

| Test class and method | What it validates |
|---|---|
| `HappyPath.e2ePurchaseFlow` | Valid login, products page, Backpack and Bike Light cart addition, checkout, `$39.98` item subtotal, and order confirmation |
| `InvalidLoginTest.invalidLoginTest` | Invalid username/password are rejected and the error contains `Username and password do not match` |
| `EmptyCredentialsTest.emptyCredentialsTest` | Submitting blank login fields shows `Username is required` |
| `CartAddRemoveTest.verifyAddAndRemoveProductsFromCart` | Both selected products are initially in the cart; removing the Backpack leaves the Bike Light |
| `CheckoutValidationTest.verifyEmptyCheckoutFieldsValidation` | Continuing from checkout with all fields blank shows `First Name is required` |

The separate `FailureScreenshotDemoTest.demonstratesFailureScreenshotReporting` waits for visible login controls and then calls `Assert.fail(...)` with an intentional-failure message. Its one failure is expected when running the demo command; it is not one of the five permanent test cases. More detailed steps and run-specific result notes are in [docs/test-cases.md](docs/test-cases.md).

## Prerequisites and setup

1. Install a JDK 25 or later JDK that can compile Java release 25 code. The project's compiler target is 25.
2. Install Maven and Google Chrome.
3. Ensure the machine can access `https://www.saucedemo.com/`. Selenium may also need network access to retrieve a matching ChromeDriver.
4. Open the project root, `SauceDemo_Submission`, in VS Code or a terminal.

No separate application server or database is required.

### VS Code

Open the project folder in VS Code. Install/use the Java language support and Maven support available in your environment, then open the integrated terminal at the project root and run the commands below. The repository includes `.vscode/settings.json`, but no project-specific test task is required; Maven is the authoritative runner.

### Terminal

From the project root in PowerShell, Command Prompt, or a terminal configured with Maven:

```powershell
mvn -version
java -version
mvn clean test
```

The installed `java` and `mvn` must resolve to an environment compatible with the Java 25 compiler target.

## Running tests

### Run the five permanent tests

```bash
mvn clean test
```

This is the normal submission command. Surefire includes the five permanent scenarios and excludes `FailureScreenshotDemoTest`.

### Run only the intentional failure demo

```bash
mvn -Dtest=FailureScreenshotDemoTest test
```

This explicitly selected test runs by itself despite the class's default exclusion. **A non-zero Maven result / `BUILD FAILURE` is expected** because the test deliberately calls `Assert.fail("Live demo: intentional failure to verify screenshot reporting")`. This expected demo failure must not be interpreted as a failure of the five-test suite.

The demo writes to the same generated ExtentReports output as the normal suite. Run `mvn clean test` afterward to restore the current generated report to a normal-suite report. The demo report and its screenshot are not automatically copied into `submission-evidence/`.

### Run one permanent test

For example:

```bash
mvn -Dtest=CheckoutValidationTest test
```

An explicit class selection runs the selected test rather than the default complete suite.

## Reports and saved evidence

### Generated output for the most recent Maven invocation

- **ExtentReports HTML:** `target/extent-reports/index.html`
- **Failure screenshots:** `target/extent-reports/screenshots/<class>_<method>_<timestamp>.png`
- **Surefire text and XML results:** `target/surefire-reports/`

ExtentReports shows each test's recorded status, event details, assertion/exception information when applicable, and linked failure screenshots. Surefire produces per-class text summaries and XML. These outputs describe the most recent relevant run; an intentional demo invocation replaces the generated ExtentReports HTML with demo results.

### Preserved submission evidence

- `submission-evidence/final-run/index.html` and `submission-evidence/final-run/surefire-reports/` preserve the successful five-test run.
- `submission-evidence/live-failure-demo-reusable/index.html`, its `screenshots/` subfolder, and `org.testCases.FailureScreenshotDemoTest.txt` preserve the deliberate failure demonstration.

These are fixed copies of the runs recorded when they were saved. They do not update when tests are rerun. Preserve or copy new evidence separately if a newer archival record is needed. The `mvn clean` phase removes `target/`, but does not remove `submission-evidence/`.

See [docs/test-execution-summary.md](docs/test-execution-summary.md) for the recorded run details and [docs/test-cases.md](docs/test-cases.md) for per-scenario results.

## Browser lifecycle and failure screenshots

`BaseTest` creates a `ChromeDriverService` and a `ChromeDriver` in `@BeforeMethod`, applies an implicit wait, maximizes the window, navigates to SauceDemo, and creates the page objects used by that test.

The existing `@AfterMethod(alwaysRun = true)` first writes the test outcome to ExtentReports. For a failed test, it takes the screenshot and attaches a relative path to the report entry **before** closing the browser. Its `finally` cleanup calls `driver.quit()` and stops the associated `ChromeDriverService`. Finally, `@AfterSuite` calls `extent.flush()` to write the report. Screenshot capture is available only if the browser has started and WebDriver supports screenshots; a failure before browser initialization may have no browser image.

## Expected normal-suite outcome

The expected outcome is five tests executed, five passed, no failures, errors, or skipped tests, followed by Maven `BUILD SUCCESS`. This is an expectation, not a guarantee: network, browser, site, or environment changes can cause a run to fail. Always use the output and report from the particular run as the actual result.

## Troubleshooting

| Symptom | Checks |
|---|---|
| `mvn` or `java` is not recognized | Install Maven/JDK and update `PATH`; reopen the terminal and check `mvn -version` and `java -version`. |
| Java release 25 is unsupported | Maven is using an older JDK. Point `JAVA_HOME` and `PATH` to a JDK that supports release 25. |
| Chrome fails to start or ChromeDriver cannot be obtained | Confirm Chrome is installed, network access is available for driver resolution, and no incompatible manually configured driver is taking precedence. Review the Maven/Selenium error before changing code. |
| SauceDemo page cannot load | Check internet connectivity and whether `https://www.saucedemo.com/` is reachable in a browser. |
| Test fails on an assertion | Read the Surefire result in `target/surefire-reports/`, open `target/extent-reports/index.html`, and inspect any failure screenshot before changing selectors or expected values. |
| Report seems to show the wrong run | `target/extent-reports/index.html` is overwritten by the next test execution, including the intentional demo. Re-run `mvn clean test` for the five-test report. |
| A report path is missing after `mvn clean test` | `clean` removes `target/` first; successful execution recreates report output. Use preserved `submission-evidence/` copies for prior evidence. |
| No screenshot is attached | Confirm the failure happened after WebDriver startup and that the report's relative screenshot file exists under `target/extent-reports/screenshots/`. |

## Limitations and possible improvements

- Tests depend on the live public SauceDemo site and browser behavior; they are not fully isolated from external changes.
- The current scenarios cover selected login, cart, and checkout paths, not every page, product, browser, or failure condition.
- Credentials and checkout values are test data in source code for this public training site. A real application should use appropriate secret management and test accounts.
- The project targets Java release 25 and requires a compatible local JDK and browser environment.
- Future enhancements could include richer cross-browser coverage, additional negative scenarios, CI execution, and stronger test-data configuration. These are possibilities, not current implemented capabilities.
